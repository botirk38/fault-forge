\begin{abstract}
% ===========================================================================

Slow faults (transient performance degradations such as network delays, disk
stalls, and CPU throttling) are a leading cause of catastrophic failures in
production distributed systems. Existing tools like \xinda{} explore the
\emph{impact} of configured slow faults using exhaustive grid search, but
require manual grid design and cannot characterize the \emph{minimal} fault
that triggers a vulnerability. We present \system{}, a symptom-guided fault
reproduction orchestrator that, given a production issue symptom, automatically
synthesizes a minimal fault recipe that reproduces it.

\system{} introduces a greedy dimensional minimizer that uses binary search
over continuous fault parameter spaces (severity, duration, timing, and fault
count) to converge on the boundary between safe and dangerous operation.
Unlike grid-based approaches, \system{} adapts to the system under test and
guarantees convergence in $O(\log_2 n)$ iterations per dimension.

We evaluate \system{} across \textbf{10 production distributed systems}
(etcd, ZooKeeper, MongoDB, Redis, TiKV, Cassandra, HBase, Kafka, CockroachDB,
Hadoop) under \textbf{five fault types} (network, filesystem, CPU, memory,
process). Across 50 system--fault configurations, \system{} uses
\textbf{52\% fewer trials} on average and completes \textbf{2.1$\times$
faster} than \xinda{}'s exhaustive grid while producing actionable minimal
fault recipes. Critically, \system{} discovers vulnerabilities that fall
outside fixed grids: Redis Cluster's failure boundary at 2.7\,s is entirely
invisible to \xinda{}'s network grid (which covers up to 1\,s), and several
filesystem boundaries exceed standard severity ranges. Our results reveal
that consensus-based systems universally trigger catastrophic leader elections
under sub-20\,ms network delay, which is 250$\times$ below typical operator
alerting thresholds (as documented in industry SRE reports), demonstrating
that slow faults pose a far greater threat than current monitoring practices
address.

Repeated trials across five independent runs per configuration confirm the
stability of these boundaries (coefficient of variation $<5\%$ for network
faults), validating the monotonicity assumption that underpins binary search.
Multi-fault experiments demonstrate that combining fault types can lower
individual boundaries by up to 40\%, revealing interaction effects invisible
to single-fault testing.

\end{abstract}
