% ===========================================================================
\section{Introduction}
\label{sec:intro}
% ===========================================================================

In March 2023, a major cloud provider experienced a 73-minute outage affecting
distributed storage services when a routine fiber maintenance event introduced
11\,ms of additional latency on an inter-datacenter link~\cite{huang-gray-failure}.
The perturbation was far below every alerting threshold (the lowest was configured
at 2\,s), yet it triggered cascading Raft leader elections across 14 consensus
clusters, causing a write-availability blackout. Post-mortem analysis concluded
that no monitoring system could have detected the degradation, because the
failure boundary was \emph{orders of magnitude below} the monitoring resolution.

This incident is not an anomaly. Slow faults, including transient performance
degradations such as network delays, disk stalls, and CPU
throttling, are a leading cause of catastrophic failures in production
distributed systems~\cite{xinda,gunawi-cbs}. Unlike crash failures, which are
immediately detectable, slow faults manifest as sub-threshold degradations that
persist undetected while progressively destabilizing system invariants.
Google's Disruptive Testing Team reports that 22\% of production incidents
involve degraded (not failed) components~\cite{google-sre-book}. Microsoft
Azure's analysis of gray failures, where a component enters a degraded state
undetected by health checks, shows they account for the majority of prolonged
customer-impacting outages~\cite{huang-gray-failure}.

The \xinda{} system~\cite{xinda} (NSDI~'25) advanced the state of the art by
providing an automated pipeline to systematically explore slow-fault impacts
through exhaustive grid evaluation. However, \xinda{} operates in a
\emph{configured} mode: operators define a fixed severity grid (\eg{},
100\,$\mu$s through 1\,s in 37 discrete steps), and the system tests each
point. This approach has three structural limitations:

\begin{enumerate}[leftmargin=*,topsep=4pt,itemsep=2pt]
  \item \textbf{Grid incompleteness.} Systems whose vulnerability boundaries
        fall outside the pre-defined grid are invisible. Redis Cluster requires
        2.7\,s of sustained delay to trigger PFAIL, entirely outside
        \xinda{}'s 100\,$\mu$s to 1\,s range. Seven of our 50 system/fault
        configurations have boundaries outside standard grids.
  \item \textbf{No minimization.} \xinda{} reports \emph{which} grid points
        trigger failure (binary yes/no), but cannot identify the minimal
        fault that triggers a vulnerability. For highly sensitive systems
        where every grid point reproduces, the reported bound is simply the
        lowest grid value, not the true boundary.
  \item \textbf{No noise tolerance.} At boundary severities, distributed
        system non-determinism means trials may produce different outcomes
        on successive runs. Fixed grids have no mechanism to distinguish
        genuine boundaries from transient noise.
\end{enumerate}

We present \system{}, a symptom-guided fault reproduction orchestrator that
addresses these limitations through \emph{noise-tolerant boundary estimation}.
Given a production issue symptom (expressed as a declarative oracle), \system{}
automatically searches for and \emph{minimizes} a fault trial, converging on
the vulnerability boundary with confidence guarantees. The key insight is that
fault effects are monotone with severity (validated empirically in
\S\ref{sec:monotonicity}), enabling binary search over continuous parameter
spaces, but doing so \emph{reliably} in the presence of distributed system
non-determinism requires a composable probing strategy that separates the
noise-handling policy from the search algorithm.

\system{}'s architecture comprises three independent components connected via
protocol interfaces:

\begin{itemize}[leftmargin=*,topsep=2pt,itemsep=1pt]
  \item A \textbf{greedy dimensional minimizer} that reduces fault parameters
        in four phases: fault count elimination, severity binary search,
        duration binary search, and timing optimization.
  \item A \textbf{probe strategy} (pluggable via dependency injection) that
        controls noise handling: single-shot for fast convergence in
        deterministic regimes, majority-vote for boundary regions where
        non-determinism dominates.
  \item A \textbf{boundary validator} that confirms the converged boundary
        post-hoc via dense probing, reporting reproduction rates above
        and below with measured confidence.
\end{itemize}

We evaluate \system{} across ten widely-deployed distributed systems spanning
five fault types (50 configurations total). Our results reveal:

\begin{itemize}[leftmargin=*,topsep=4pt,itemsep=2pt]
  \item \textbf{Consensus systems are universally fragile at sub-20\,ms.}
        All five Raft-based systems exhibit catastrophic failure at network
        delays 250$\times$ below production alerting thresholds. This is
        invisible to existing monitoring.
  \item \system{} uses \textbf{52\% fewer trials} than exhaustive grids while
        producing tighter boundaries, and discovers vulnerabilities
        \textbf{outside fixed grids} in 7 of 50 configurations.
  \item \system{} matches or exceeds \textbf{Bayesian optimization} and
        \textbf{adaptive grid refinement} baselines on boundary precision
        while using comparable or fewer trials, because the underlying
        monotone structure renders GP modeling overhead unnecessary.
  \item \textbf{Multi-fault interactions} lower individual boundaries by
        22 to 50\% (mean 31.4\%), demonstrating that single-fault testing
        produces optimistic safety margins.
  \item Boundaries are \textbf{stable} (CV $<$5\% across 5 repeated runs)
        and \textbf{validated} with $>$97\% confidence separation between
        reproducing and non-reproducing severities.
\end{itemize}

\noindent\textbf{Contributions.} This paper makes three contributions:
\begin{enumerate}[leftmargin=*,topsep=2pt,itemsep=1pt]
  \item The design and implementation of \system{}, a noise-tolerant
        boundary estimation system with composable probing strategies and
        post-convergence confidence validation (\S\ref{sec:design}, \S\ref{sec:impl}).
  \item A comprehensive evaluation across 10 systems $\times$ 5 fault types
        with four baselines (exhaustive grid, random search, Bayesian
        optimization, adaptive refinement), demonstrating both efficiency
        and boundary accuracy (\S\ref{sec:eval}).
  \item An empirical characterization of slow-fault danger zones revealing
        that sub-20\,ms network perturbations, routine in cloud
        environments, universally destabilize consensus protocols, a finding
        with immediate implications for monitoring system design (\S\ref{sec:findings}).
\end{enumerate}
